# 커밋 전 코드 검토

## 참조 파일
- 검토 기준: [conventions.md](conventions.md)

## 절차

1. **변경된 코드 가져오기**
   - `git status`로 현재 브랜치와 변경된 파일 목록을 확인한다.
   - `git diff HEAD`로 아직 커밋하지 않은 변경 내용(스테이징 포함)을 가져온다.
   - 새로 추가된(untracked) 파일은 파일 내용을 직접 읽어서 검토 대상에 포함한다.
   - 변경 사항이 없으면 "검토할 변경 사항이 없습니다."라고 알리고 끝낸다.

2. **컨벤션 기준으로 검토하기**
   - [conventions.md](conventions.md)를 읽고, 그 안의 각 규칙을 변경된 코드에 적용한다.
   - 변경되지 않은 기존 코드는 검토하지 않는다.
   - 규칙마다 결과를 **✅ 통과** 또는 **⚠️ 개선 필요**로 표시한다. 아래 형식의 표로 정리한다.

     | 구분 | 규칙 | 결과 | 위치 |
     |------|------|------|------|
     | 네이밍 | 변수명, 함수명은 카멜 케이스 | ✅ 통과 | - |
     | 코드 품질 | console.log 제거 | ⚠️ 개선 필요 | `src/lib/rss.ts:42` |

3. **개선 방법 안내하기**
   - '개선 필요' 항목마다 문제가 되는 위치(`파일:줄번호`)와 이유를 적는다.
   - 수정 전/후 코드 예시를 함께 보여 준다.

     ```ts
     // 수정 전
     console.log(articles);

     // 수정 후
     // (디버깅용 console.log 삭제)
     ```

   - 검토만 하고, 사용자가 요청하기 전에는 파일을 직접 수정하지 않는다.

4. **결과 마무리**
   - 모든 항목이 '통과'라면 `커밋 준비가 완료되었습니다!`를 출력한다.
   - '개선 필요' 항목이 있으면 개수를 요약하고, 수정 후 다시 `/convention-check`를 실행하도록 안내한다.
