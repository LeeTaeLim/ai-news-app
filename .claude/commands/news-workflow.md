# 뉴스 수집기 새 기능 개발 워크플로

뉴스 수집기 앱에 새 기능을 개발할 때 아래 과정을 순서대로 실행해.
브랜치 이름: $ARGUMENTS

## 1. 현재 상태와 브랜치 확인

1. `git status`로 현재 작업 상태를 확인하고, 커밋하지 않은 변경이 있으면 목록을 알려 줘.
2. `git branch --show-current`로 현재 브랜치를 확인해.
3. main 브랜치라면 "현재 main 브랜치입니다."라고 알려 주고 다음 단계로 넘어가.
4. main이 아니라면 "⚠️ 현재 브랜치는 main이 아닙니다 (현재: <브랜치 이름>)."라고 경고하고, main으로 이동할지 사용자에게 물어봐.
   - 사용자가 이동을 원하면 `git switch main`으로 이동해. 커밋하지 않은 변경 때문에 이동이 실패하면 그 이유를 알려 주고 어떻게 할지 다시 물어봐.
   - 사용자가 원하지 않으면 현재 브랜치에서 그대로 진행해.

## 2. 새 브랜치 만들기

1. 위의 "브랜치 이름"이 비어 있지 않으면 그 이름으로 `git switch -c <브랜치 이름>`을 실행해.
2. 비어 있으면 어떤 기능을 개발할 것인지 사용자에게 물어봐. 답을 받으면 영어 소문자와 하이픈만 쓴 브랜치 이름을 제안해 (예: 카테고리 필터 → `category-filter`). 사용자가 확인하거나 다른 이름을 주면 그 이름으로 브랜치를 만들어.
3. 같은 이름의 브랜치가 이미 있으면 알려 주고 다른 이름을 제안해.

## 3. 개발 시작 안내

1. 브랜치를 만들었으면 "이제 개발을 시작하세요!"라고 안내해.
2. `CLAUDE.md`(와 거기서 참조하는 `AGENTS.md`)를 읽고, 이 프로젝트의 기술 스택과 컨벤션을 짧게 정리해서 다시 알려 줘. 최소한 아래 내용을 포함해:
   - 스택: Next.js 16(App Router, `cacheComponents`), React 19, Tailwind CSS v4, Clerk, Neon + Drizzle, Anthropic SDK, rss-parser
   - Next.js 16은 학습 데이터와 다르므로 코드를 쓰기 전에 `node_modules/next/dist/docs/`의 가이드를 확인할 것
   - 인증: `src/proxy.ts`의 `clerkMiddleware()`, 보호된 페이지·Server Function·route handler에서는 `requireUserId()` 호출
   - 모든 DB 읽기·쓰기는 Clerk `userId`로 범위를 제한할 것
   - 화면은 `DESIGN.md`와 `ui.md`를 따르고, UI 언어는 한국어
   - 명세는 `PRD.md`이며, §11의 범위 밖 기능은 요청 없이 만들지 않을 것
   - 확인 명령: `npm run dev`, `npm run build`(타입 검사 포함), `npm run lint`
3. 사용자가 "완료" 또는 "done"이라고 입력할 때까지 개발을 도와줘.

## 4. 완료 후 커밋과 병합

사용자가 "완료" 또는 "done"이라고 입력하면:

1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여 줘.
2. 변경 내용을 보고 커밋 메시지를 제안해. 이 저장소의 기존 커밋처럼 한국어 한 줄로, "~ 추가", "~ 수정"처럼 무엇을 했는지 쓴다 (`git log --oneline -5`로 스타일을 확인해).
3. 사용자가 확인하면 변경을 커밋해. 사용자가 메시지를 고치면 고친 메시지로 커밋해.
4. `git switch main`으로 이동한 뒤 `git merge <브랜치 이름>`으로 병합해.
5. 병합 중 충돌이 나면 멈추고, 충돌한 파일을 알려 준 뒤 어떻게 할지 사용자에게 물어봐.

## 5. 작업 요약

병합이 끝나면 다음 내용을 요약해서 보여 줘:

- 작업한 브랜치 이름
- 커밋 메시지와 커밋 해시
- 변경된 파일 목록 (추가·수정·삭제 구분)
- 구현한 기능의 핵심 내용 몇 줄
- 현재 브랜치(main)와, 원격(origin)에 아직 푸시하지 않았다는 안내
